# PUMP

Музыкальный плеер на основе Liquid Glass для браузера и Telegram Mini App. Сервер на Rust обслуживает интерфейс, каталог, WebSocket-комнаты и статистику SQLite. Бот работает через Teloxide.

## Cargo Workspace

Сервер запускается прежним бинарным файлом `pump`. В workspace находятся восемь крейтов.

| Крейт | Назначение |
| --- | --- |
| `core-streaming` | Каталог, InnerTube, сессионная подпись, выбор потоков и HTTP Range proxy |
| `audio-dsp-engine` | PCM, Symphonia, Rubato/WSOLA, EQ, реверберация, анализ громкости, сведение и очередь |
| `lyrics-engine` | Параллельный запрос текстов, Enhanced LRC/TTML, временные границы слов и голосов |
| `library-storage` | SQLite сессий и статистики, загрузки, аудиотеги, обложки, WebDAV и SMB |
| `social-integrations` | Spotify PKCE, Apple metadata, Last.fm, Discord IPC и локальные FFT-отпечатки |
| `plugin-spine` | WASM ABI, лимиты памяти/топлива/времени, поиск и резервные качества |
| `telegram-bridge` | Сервер Axum, бот, webhook, пульт Mini App, импорты и распознавание |
| `ui-liquid-glass` | Ресурсы приложения и Rust/WASM-утилиты интерфейса |

Браузер воспроизводит аудио через WebAudio. Эквалайзер, Concert Mode и live pitch-shift выполняются в Rust/WASM внутри AudioWorklet. Управление интерфейсом пока написано на JavaScript. Нативный DSP также предоставляет Rust API. Дополнительные возможности включаются Cargo features `audio-dsp-engine/native-output`, `audio-dsp-engine/dlna`, `library-storage/smb`, `social-integrations/discord`. Для ALSA на Linux нужен пакет `libasound2-dev`.

## Дополнительные интеграции

`PUMP_YOUTUBE_COOKIES` включает сессионную подпись запросов InnerTube. Сервер перебирает клиентские профили и возвращает доступные прямые форматы через `/api/streams/{id}`. Форматы с шифрованной подписью, ограничения аккаунта и блокировки со стороны YouTube могут потребовать встроенный видеоплеер. Cookies хранятся в секретах окружения.

Для импорта Spotify свой Client ID не обязателен. В настройках библиотеки вставь публичную ссылку плейлиста. Сервер читает доступные метаданные Spotify Embed и ищет совпадения в каталоге PUMP. Spotify иногда скрывает часть списка или не отдаёт Embed. В таком случае экспортируй список через [Exportify](https://exportify.app/) и выбери CSV в настройках PUMP. CSV сохраняет порядок, повторы и названия на русском. Импорт переносит список треков, аудио воспроизводится из доступных источников PUMP.

POST `/api/import` принимает `source` (`spotify` или `apple`) и `link`, POST `/api/import/csv` — файл CSV. Ответ `202` содержит `job_id`; GET `/api/import/{job_id}` показывает прогресс и итог сопоставления. Запросы требуют сессию пользователя. Интерфейс показывает неоднозначные совпадения и возможное усечение Embed.

`SPOTIFY_CLIENT_ID` дополнительно включает OAuth через POST `/api/spotify/authorize`. Для него нужно зарегистрировать публичный callback `/api/spotify/callback` в Spotify Developer Dashboard. Подключение хранится в памяти процесса. Публичные ссылки Apple обрабатываются в пределах метаданных iTunes Lookup; для полноценного импорта плейлистов требуется MusicKit.

`LASTFM_API_KEY` и `LASTFM_SHARED_SECRET` задают приложение Last.fm. Пользователь подключает свой session key в настройках библиотеки. Ключ сессии хранится в памяти, а события на повторную отправку — в локальном файле пользователя.

`AUDD_TOKEN` включает распознавание голосовых сообщений и кружочков, пересланных в бот, и POST `/api/recognize` с бинарным аудио. Самостоятельная библиотека отпечатков ищет по записям, которые приложение заранее проиндексировало. Глобальную базу распознавания предоставляет AudD.

Команды `/play название`, `/queue название`, `/pause`, `/next`, `/previous`, `/seek секунды`, `/eq десять_значений` управляют открытой Mini App той же Telegram-сессии. `/stats` и `/stats month` отправляют PNG-карточку с итогами. Проверка этих команд требует подключения Telegram и действий пользователя в Mini App.

Загрузки сервера доступны через `/api/downloads`, POST `/api/downloads/{id}` и авторизованный GET `/api/downloads/{id}/file`. Клиентская кнопка скачивания сохраняет аудио на устройстве в IndexedDB. «Скачать очередь» сохраняет весь текущий список, включая импортированный плейлист, пропускает уже загруженные записи и позволяет остановить загрузку. Настройка «Только офлайн» отключает запросы к API и оставляет локальные записи. Постоянное облачное хранилище подключается на заключительном этапе проекта.

WASM-провайдеры описаны в [ABI](crates/plugin-spine/ABI.md). Файлы загружаются из `PUMP_PLUGIN_DIR` при запуске и появляются в списке источников поиска. Сервер выдаёт отдельные временные ссылки, поддерживает HTTP Range и разрешает только хосты из `PUMP_PLUGIN_ALLOWED_HOSTS`. Плеер пробует следующий формат при ошибке. Настройка и рабочий пример SoundHelix приведены в [руководстве по плагинам](providers/README.md).

### NAS

Укажи `PUMP_NAS_CONFIG=./nas.json` и создай файл конфигурации. `owners` содержит владельцев, которым разрешён доступ. Для Telegram используй свой числовой ID в формате `telegram:123456789`.

```json
[
  {
    "protocol": "webdav",
    "id": "home",
    "name": "Домашняя музыка",
    "base": "https://nas.example.com/music/",
    "username": "music",
    "password": "пароль NAS",
    "owners": ["telegram:123456789"]
  }
]
```

После перезапуска открой сетевую библиотеку в настройках и введи относительный путь, например `Albums/Track.flac`. Аудио передаётся частями через сервер, без полного скачивания. В конфигурации можно задать `protocol: "smb"`, `server`, `share`, `username`, `password` и тот же `owners`; такая сборка требует `cargo build --release --features smb`. Сервер должен иметь сетевой доступ к NAS. Пароли остаются в файле конфигурации сервера.

## Пересборка браузерного WASM

Готовые файлы `web/pkg` входят в исходники и используются сервером. После изменения Rust-функций интерфейса их можно обновить.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked
cargo build -p ui-liquid-glass --target wasm32-unknown-unknown --release
wasm-bindgen --target web --out-dir web/pkg --out-name ui_liquid_glass target/wasm32-unknown-unknown/release/ui_liquid_glass.wasm
cargo build -p ui-liquid-glass --release --target wasm32-unknown-unknown --no-default-features --features dsp-only
cp target/wasm32-unknown-unknown/release/ui_liquid_glass.wasm web/pkg/pump_dsp.wasm
```

Первый модуль предоставляет утилиты интерфейса. Второй не требует JS-импортов и обрабатывает PCM в AudioWorklet. После изменения файлов `web/pkg` пересобери сервер, поскольку ресурсы встраиваются в бинарный файл.

## Запуск на компьютере

1. Установи стабильный Rust через [rustup](https://rustup.rs/). Для сборки на Linux тоже понадобятся компилятор C и linker (пакет `build-essential` на Debian/Ubuntu).
2. Скопируй настройки и собери сервер.

   ```sh
   cp .env.example .env
   cargo build --release --locked
   ./target/release/pump
   ```

   Отдельно открывать HTML-файл не нужно. Плеер и его API доступны по [http://127.0.0.1:8080](http://127.0.0.1:8080). Полные демозаписи предоставлены [SoundHelix](https://www.soundhelix.com/audio-examples). Обложки демо сохранены из исходного HTML. [Первая](https://images.unsplash.com/photo-1614613535308-eb5fbd3d2c17) · [Вторая](https://images.unsplash.com/photo-1518709268805-4e9042af9f23) · [Третья](https://images.unsplash.com/photo-1470225620780-dba8ba36b745)

3. Чтобы слушать собственные записи, создай папку `music`, добавь файлы и укажи `PUMP_MEDIA_DIR=./music` в `.env`. После перезапуска сервер прочитает теги и встроенные обложки. Перемотка использует HTTP Range. Поддержка конкретного кодека зависит от браузера. На публичном сервере добавляй в эту папку только записи, которыми можно делиться с другими.

В поиске «Полные записи» показывает файлы медиатеки и демозаписи, «Превью iTunes» — фрагменты из открытого каталога, «YouTube» — видео в официальном встроенном плеере при разрешённом встраивании. Для поиска YouTube можно задать `YOUTUBE_API_KEY` из Google Cloud. Без ключа используется публичный поиск InnerTube, доступность которого зависит от YouTube. Ссылки на отдельные видео принимаются и без ключа. Синхронные тексты песен, если есть в каталоге, загружаются из LRCLIB.

## Telegram и телефон

1. Создай бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и включи inline-режим командой `/setinline`.
2. Запусти сервер на хостинге с публичным HTTPS-адресом. Настрой прокси на порт приложения с передачей заголовка `Host` и поддержкой WebSocket. Укажи в настройках хостинга или локальном `.env` следующие значения.

   ```dotenv
   BIND_ADDR=0.0.0.0
   PORT=8080
   TELOXIDE_TOKEN=токен_BotFather
   WEBAPP_URL=https://pump.example.com
   ```

   `WEBAPP_URL` — корневой адрес приложения. Telegram запрашивает inline-MP3 по HTTPS, поэтому этот же адрес должен быть доступен извне. Токен храни в настройках хостинга или в `.env`. Для одного токена запускай один экземпляр сервера с ботом.

3. Отправь боту `/start` в личном чате и нажми «Открыть PUMP». Через `@имя_бота название` можно отправить MP3 из медиатеки в чат. `/stats` показывает итог за неделю для аккаунта Telegram. В браузере сессия хранится локально, а в Mini App статистика привязана к Telegram ID после серверной проверки подписи `initData`.

В разделе «Комната» создай комнату и отправь другу её код. Друг вводит его и нажимает «Включить звук». Выбор трека, воспроизведение и перемотка следуют за ведущим. Синхронизация и статистика учитывают записи с прямым аудиопотоком, включая превью. Встроенные видео YouTube управляются через плеер YouTube. Статистика за 7 и 30 дней доступна в разделе «Итоги». Комнаты хранятся в памяти процесса, история прослушиваний — в `PUMP_DATA_DIR/pump.sqlite`.

## Render

Подключи репозиторий как Blueprint с `render.yaml`. Для существующего Web Service выбери runtime Docker и укажи `/healthz` в поле Health Check Path. Добавь `TELOXIDE_TOKEN` в Environment сервиса. Render передаст порт и публичный адрес автоматически. Если плеер будет открываться на своём домене, можно явно задать `WEBAPP_URL`.

На Render бот принимает webhook. Входящий запрос Telegram может разбудить бесплатный сервис. Бесплатный диск эфемерный, поэтому новый деплой или перезапуск может сбросить историю. Для сохранения SQLite на постоянном диске подключи его к `/app/data` и предоставь пользователю контейнера (UID 10001) доступ на запись.

## Docker и GitHub Actions

```sh
docker build -t pump .
docker run --rm -p 127.0.0.1:8080:8080 -v pump-data:/app/data pump
```

Для запуска с `.env` добавь `--env-file .env -e BIND_ADDR=0.0.0.0 -e PUMP_DATA_DIR=/app/data` перед именем образа. Чтобы передать локальные треки, добавь `-v "$PWD/music:/app/music:ro" -e PUMP_MEDIA_DIR=/app/music`. В контейнере приложение работает от UID 10001, которому нужно право чтения файлов музыки.

Если Docker собирается за прокси с собственным центром сертификации, передай доверенный для этой сети пакет сертификатов через `docker build --secret id=cargo_ca,src=/путь/к/ca-bundle.crt -t pump .`. Пакет используется только при скачивании Rust-зависимостей.

С телефона распакуй архив и загрузи исходники в свой репозиторий, сохранив пути, в том числе `.github/workflows`. Для файлов со скрытыми путями можно открыть репозиторий в веб-редакторе [github.dev](https://github.dev). Workflow `Проверка PUMP` запускается на push и pull request. Для публикации образа в GHCR запусти `Публикация образа PUMP` во вкладке Actions или создай релиз. На Docker-хостинге укажи репозиторий с Dockerfile либо опубликованный образ. Для сохранения истории между запусками подключи постоянный том к `/app/data`.

cargo fmt --all -- --check

cargo test --workspace --locked

Браузерным тестам нужен FFmpeg. Они поднимают сервер с отдельной SQLite, проверяют HTTP Range и воспроизведение в двух мобильных сессиях Chromium без токена Telegram. `GET /healthz` возвращает состояние процесса для хостинга.

## Границы текущей реализации

Rust/WASM уже обрабатывает браузерный аудиотракт — EQ/AutoEq, Concert Mode и pitch-shift. Управление экраном и очередью остаётся на JavaScript. Живой pitch-shift использует ограниченный зерновой алгоритм; автономный WSOLA доступен в Rust API.

Публичный импорт Spotify и CSV работают без Client ID. Для проверки OAuth личного аккаунта, Last.fm и AudD нужны соответствующие данные. SMB/DLNA/Discord и аудиоустройства проверяются сборкой отдельно от подключения к реальному оборудованию.

В YouTube ещё требуется поддержка signatureCipher/n-signature и связанных ограничений источника. Точность комнат 200 мс проверена локально и требует измерений на пользовательской сети. Нативные Crossfade/Automix/DJ API предстоит встроить в браузерное воспроизведение. Полное приложение на Rust/WASM, импорт плейлистов Apple через MusicKit, каталог настроений, полноценный файловый браузер NAS, сетевые host-вызовы для динамических WASM-провайдеров и системные виджеты остаются в работе. Постоянная облачная БД и файловое хранилище подключаются на заключительном этапе.

Подробная сверка с ТЗ находится в [статусе реализации](docs/IMPLEMENTATION_STATUS.md). Использованные open-source проекты и лицензии перечислены в [OPEN_SOURCE.md](OPEN_SOURCE.md).
