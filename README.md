# PUMP

Музыкальный плеер на основе Liquid Glass для браузера и Telegram Mini App. Сервер на Rust обслуживает интерфейс, каталог, WebSocket-комнаты и статистику SQLite. Бот работает через Teloxide.

## Запуск на компьютере

1. Установи стабильный Rust через [rustup](https://rustup.rs/). Для сборки на Linux тоже понадобятся компилятор C и linker (пакет `build-essential` на Debian/Ubuntu).
2. Скопируй настройки и собери сервер.

   ```sh
   cp .env.example .env
   cargo build --release --locked
   ./target/release/pump
   ```

   Отдельно открывать HTML-файл не нужно. Плеер и его API доступны по [http://127.0.0.1:8080](http://127.0.0.1:8080). Полные демозаписи предоставлены [SoundHelix](https://www.soundhelix.com/audio-examples). Обложки демо сохранены из исходного HTML. [Первая](https://images.unsplash.com/photo-1614613535308-eb5fbd3d2c17) · [Вторая](https://images.unsplash.com/photo-1518709268805-4e9042af9f23) · [Третья](https://images.unsplash.com/photo-1470225620780-dba8ba36b745)

3. Чтобы слушать собственные записи, создай папку `music`, добавь файлы и укажи `PUMP_MEDIA_DIR=./music` в `.env`. После перезапуска сервер прочитает теги и встроенные обложки. Перемотка использует HTTP Range. Поддержка конкретного кодека зависит от браузера. На публичном сервере добавляй в эту папку только записи, которыми можно делиться с другими.

В поиске «Полные записи» показывает файлы медиатеки и демозаписи, «Превью iTunes» — фрагменты из открытого каталога, «YouTube» — видео в официальном встроенном плеере при разрешённом встраивании. Для поиска YouTube можно задать `YOUTUBE_API_KEY` из Google Cloud. Без ключа используется публичный поиск InnerTube, доступность которого зависит от YouTube. Ссылки на отдельные видео принимаются и без ключа. Синхронные тексты песен, если есть в каталоге, загружаются из LRCLIB.

## Telegram и телефон

1. Создай бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и включи inline-режим командой `/setinline`.
2. Запусти сервер на хостинге с публичным HTTPS-адресом. Настрой прокси на порт приложения с передачей заголовка `Host` и поддержкой WebSocket. Укажи в настройках хостинга или локальном `.env` следующие значения.

   ```dotenv
   BIND_ADDR=0.0.0.0
   PORT=8080
   TELOXIDE_TOKEN=токен_BotFather
   WEBAPP_URL=https://pump.example.com
   ```

   `WEBAPP_URL` — корневой адрес приложения. Telegram запрашивает inline-MP3 по HTTPS, поэтому этот же адрес должен быть доступен извне. Токен храни в настройках хостинга или в `.env`. Для одного токена запускай один экземпляр сервера с ботом.

3. Отправь боту `/start` в личном чате и нажми «Открыть PUMP». Через `@имя_бота название` можно отправить MP3 из медиатеки в чат. `/stats` показывает итог за неделю для аккаунта Telegram. В браузере сессия хранится локально, а в Mini App статистика привязана к Telegram ID после серверной проверки подписи `initData`.

В разделе «Комната» создай комнату и отправь другу её код. Друг вводит его и нажимает «Включить звук». Выбор трека, воспроизведение и перемотка следуют за ведущим. Синхронизация и статистика учитывают записи с прямым аудиопотоком, включая превью. Встроенные видео YouTube управляются через плеер YouTube. Статистика за 7 и 30 дней доступна в разделе «Итоги». Комнаты хранятся в памяти процесса, история прослушиваний — в `PUMP_DATA_DIR/pump.sqlite`.

## Render

Подключи репозиторий как Blueprint с `render.yaml`. Для существующего Web Service выбери runtime Docker и укажи `/healthz` в поле Health Check Path. Добавь `TELOXIDE_TOKEN` в Environment сервиса. Render передаст порт и публичный адрес автоматически. Если плеер будет открываться на своём домене, можно явно задать `WEBAPP_URL`.

На Render бот принимает webhook. Входящий запрос Telegram может разбудить бесплатный сервис. Бесплатный диск эфемерный, поэтому новый деплой или перезапуск может сбросить историю. Для сохранения SQLite на постоянном диске подключи его к `/app/data` и предоставь пользователю контейнера (UID 10001) доступ на запись.

## Docker и GitHub Actions

```sh
docker build -t pump .
docker run --rm -p 127.0.0.1:8080:8080 -v pump-data:/app/data pump
```

Для запуска с `.env` добавь `--env-file .env -e BIND_ADDR=0.0.0.0 -e PUMP_DATA_DIR=/app/data` перед именем образа. Чтобы передать локальные треки, добавь `-v "$PWD/music:/app/music:ro" -e PUMP_MEDIA_DIR=/app/music`. В контейнере приложение работает от UID 10001, которому нужно право чтения файлов музыки.

Если Docker собирается за прокси с собственным центром сертификации, передай доверенный для этой сети пакет сертификатов через `docker build --secret id=cargo_ca,src=/путь/к/ca-bundle.crt -t pump .`. Пакет используется только при скачивании Rust-зависимостей.

С телефона распакуй архив и загрузи исходники в свой репозиторий, сохранив пути, в том числе `.github/workflows`. Для файлов со скрытыми путями можно открыть репозиторий в веб-редакторе [github.dev](https://github.dev). Workflow `Проверка PUMP` запускается на push и pull request. Для публикации образа в GHCR запусти `Публикация образа PUMP` во вкладке Actions или создай релиз. На Docker-хостинге укажи репозиторий с Dockerfile либо опубликованный образ. Для сохранения истории между запусками подключи постоянный том к `/app/data`.

## Проверки

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --locked
python3 -m venv .venv
.venv/bin/pip install playwright==1.62.0
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser.py
```

Браузерным тестам нужен FFmpeg. Они поднимают сервер с отдельной SQLite, проверяют HTTP Range и воспроизведение в двух мобильных сессиях Chromium без токена Telegram. `GET /healthz` возвращает состояние процесса для хостинга.
