# ADR-002 — независимое ядро анализа аудио (GATE 2)

Дата: 26.11.2026. Статус: реализовано, тесты зелёные, ревью назначено.

## Контекст

Automix (GATE 3) требует BPM/beatgrid/key/LUFS/секции/точки микширования.
Старый `analysis.rs` (`analyze_track`) — эвристика на огибающей с prior 120 BPM,
без STFT/chroma/key/beatgrid. Нужен профессиональный задел без сноса рабочего.

## Решение

Новый модуль `crates/audio-dsp-engine/src/music_analysis.rs` за feature `analysis`
(`dep:realfft 3.5.1`):

- Только `std` + `realfft`. Нет Axum/Tokio/DOM/Telegram. Проверено:
  `cargo check -p audio-dsp-engine --features analysis --target wasm32-unknown-unknown`
  — чисто; native/WASM — один код, детерминирован в пределах одной сборки/таргета
  (фиксированное окно/Hann без RNG, шаг = окно/4; rustfft выбирает SIMD-план
  в рантайме, libm различается — бит-в-бит кросс-таргет не обещается).
- STFT (окно адаптивно: 4096 ≤48 кГц / 8192 ≤96 кГц / 16384 выше, шаг = окно/4,
  bin ~10.7 Гц) → flux (фикс. лог-компрессия) + kick-band 160 Гц + ВЧ-контроль >2 кГц →
  onset (median+2·MAD, ≥0.15·max, ≥80 мс, сильные доли для IOI) → автокорреляция
  темпа 50–220 BPM с параболой (<1%) + октавный снап по IOI (значение — от
  автокорреляции, IOI задаёт только октаву) → фазовый beatgrid (метка = конец
  окна + полшага, квантование ±HOP/2) → HPCP-chroma (только пики + параболические
  частота и амплитуда, вес энергией) → ключ KS с лог-компрессией →
  LUFS (существующий `LoudnessMeter`) + true peak параболой вершин →
  кривая энергии/RMS-100мс (стерео-мощность), тишина −60 dBFS/200 мс
  (пик max(|L|,|R|) — противофаза не молчит), секции жадной кластеризацией
  (косинус ≥0.93, cap 8, слияние соседей — не равномерная нарезка),
  переходы MixIn/MixOut (резерв слотов)/SectionBoundary/EnergyDip.
- Память: вход — срез (единственная копия — моно-микс), хранятся только
  chroma+энергия на STFT-кадр (13 f32); лимит 300 с + потолок 28.8M кадров;
  FFT-план и буферы (mag/log/prev/scratch) переиспользуются в `MusicAnalyzer`,
  есть `reset()`; горячий цикл без аллокаций (`process_with_scratch`).
- Отмена — `&AtomicBool` (проверки каждые 32 STFT-кадра, в пиковом проходе,
  чанками громкости, перед/после тяжёлых этапов); `Error::Cancelled`.
  Для UI-потока (main thread) флага недостаточно — нужен worker + пошаговый API:
  решение GATE 3, не здесь. Версия результата `ANALYSIS_VERSION = 1`
  (чек-лист: меняешь алгоритм/пороги — бампаешь версию).
- Гейты честности: крест-фактор ≥3.0 (синкопа 3.9 проходит, шум 2.8/сустейн 2.0 —
  нет), ВЧ-гейт hf_ratio ≥0.02 (гул без транзиентов — нет; легитимный
  кик+бас-only без энергии >2 кГц тоже отсекается — осознанное ограничение),
  уверенность BPM ≥0.35, ключ только при r1 ≥0.55.

## Факты приёмки (синтетика, `cargo test -p audio-dsp-engine --features analysis`)

- BPM 60/85/90/120/128/140/160/174: ошибка ≤1% (октавный снап, парабола).
  Half-time feel (кик на 1 и 3 + хэт): сообщается доминантный пульс 70 —
  конвенция движка, удвоение по жанру — GATE 3. Weak-клики, синкопа 96,
  44.1/48/96 кГц, сплит-стерео (кик-L/хэт-R) — те же ≤1%.
- Дрейф 120→140: оценка 124–136 (near-mean, не залипание на краях), без panic.
- Beatgrid: медианная ошибка ≤20 мс на 60–174 × 44.1/48/96 кГц + kick/hat
  (центрированный сдвиг ±HOP/2; было ~100 мс из-за опережения окном —
  исправлено измерением, а не подгонкой).
- Ключ: все 24 триады (12 тоник × мажор/минор) — 100% на чистых синусах;
  обращения и октавные удвоения — та же тональность; шум и 12-тоновый
  кластер — None. 3-я+ гармоники (квинты) вне строгого гейта: красят минор
  в сторону относительного мажора, калибровка — на реальной музыке.
- LUFS: streaming vs перекрёстный эталон BS.1770 — расхождение ≤0.5 LU;
  known-answer синусы 1 кГц (−6.0) / 8 кГц (−2.8) ±0.5 LU — независимая
  проверка K-фильтра; multi-rate 44.1/96 в пределах 0.6 LU.
- True peak параболой: ловит интер-сэмпловый пик fs/4 (+0.18 над сэмплами).
- Пусто/NaN/коротко/отмена (включая mid-stream из второго потока): без panic
  (`Invalid`/`Cancelled`); лимит входа — 300 с + 28.8M кадров (тест без аллокаций).
- Старый `analyze_track` не тронут (стабилизированный компонент).

## Что не утверждаем

Синтетика ≠ доказательство качества на реальной музыке: для неё нужен
размеченный набор и отдельное измерение (явный пункт 2.5 ТЗ). Пороги 3.0/0.02/0.35
калиброваны на синтетике; рекалибровка — по реальному набору.
